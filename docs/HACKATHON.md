# 해커톤 재구현 키트 — EDCF RADAR (부정당업자 자동감지 시스템)

해커톤 현장에서 이 시스템을 **빠르게 다시 세우기 위한 대본**입니다. Claude Code(또는 Claude)에 아래 프롬프트를 순서대로 붙여넣으면 됩니다. 코드 블록 오른쪽 위 복사 버튼을 쓰세요.

- **A안 — 지금 코드 가져가기** (대회 규칙상 미리 만든 코드를 써도 될 때): 30~40분
- **B안 — 처음부터 만들기** (현장에서 새로 만들어야 할 때): 단계별 프롬프트 9개, 약 6~8시간

> 대회 규칙을 먼저 확인하세요. 규칙이 애매하면 B안으로 가되, 아래 '마스터 프롬프트'에 정리된 설계(이미 검증된 결정들)를 그대로 쓰면 시행착오 없이 빨리 갑니다.

# 무엇
EDCF 사업에 참여하는 업체(F/S·컨설턴트·본구매 계약자, 입찰·우선협상 업체)의 부정·제재 이슈를

# 구조 (서버 없이 무료 서비스만)
- 대시보드: GitHub Pages 정적 사이트 (index.html + assets/app.js + assets/style.css, Firebase JS SDK v10 CDN, 빌드 도구 없음)
- 저장소: Firebase Firestore + Google 로그인 (무료 Spark 요금제)
- 감시 프로그램: Python 3.12 (monitor/ 폴더), GitHub Actions에서 실행
- 타이머: Google Apps Script — 매일 07~08시 1번 'daily', 평일 08~19시 5분마다 'queue'(대시보드 실행 요청 처리)를
  GitHub workflow_dispatch로 보냄. (회사망은 api.github.com·script.google.com 이 막혀 있어서
  대시보드는 GitHub를 직접 부르지 않고 Firestore에 '실행 요청'만 남긴다. GitHub 자체 cron은 자주 늦거나 빠져서 보조용)
- 대시보드와 감시 프로그램은 서로 직접 연결하지 않고 Firestore로만 주고받는다.

# 등급 기준 (가장 중요 — AI 프롬프트·화면·메일 모두 같은 문장)
- 위험(red): 지금 제재 중 — 입찰참가자격 제한(부정당업자 제재)·MDB 제재·영업정지·등록말소가 현재 유효 (EXIMIIS '등록' 포함).
  뉴스는 처분이 확정·집행 중이라는 사실이 기사에 있을 때만. 예고·청문·소송 중이면 위험 아님.
- 경고(orange): 제재로 이어질 수 있는 진행 중 사안 — 최근 1년 내 수사·압수수색·기소·유죄판결, 담합 적발·공정위 과징금, 제재 처분 예고·청문, 부도·회생절차

- 공식 명단: EXIMIIS 등록=위험, 해지=주의 / 조달청 유효 제재=위험, 집행정지=경고 / MDB 이름 정확 일치=위험, 비슷함=경고

설명이 긴 문구는 화면에 늘어놓지 말고 i 아이콘(마우스를 올리면 설명)으로.

# 지킬 규칙
- 공개 저장소: 코드만. 실제 업체 명단·EXIMIIS 자료·키는 올리지 않는다(키는 GitHub Secrets, 명단은 대시보드에서 Firestore로).

- Firestore 무료 한도(하루 읽기 5만, 한국시간 17시 초기화): 대시보드 자동 새로고침은 상태 문서 1건만 읽고 바뀌었을 때만 전체 다시 읽기.

- 시각은 한국시간 문자열로 저장한다. 실행 서버는 UTC이므로 기간 계산도 한국시간 기준으로.
- 자동 매일 실행은 하루 한 번만(Apps Script와 GitHub 예약이 겹쳐도 메일 1통).
- .github/workflows/*.yml 은 사람이 마지막으로 커밋해야 예약 실행이 돈다 — 네가 만든 뒤 내가 웹에서 한 번 직접 저장한다.
- 테스트·데모에는 가상 이름('가상건설', '가나다엔지니어링' 등)만 쓴다. 대시보드 주소에 ?demo=1 을 붙이면 Firebase 없이 가상 데이터로 전체 화면이 보이게.

### 3-1. 뼈대 · 로그인 · 데모 모드 (약 1시간)

```text
1단계: 뼈대를 만들어줘.
- index.html, assets/app.js(ES 모듈), assets/style.css, assets/firebase-config.js(설정값·허용 이메일), firestore.rules
- Google 로그인 → 허용 이메일(고정 관리자 + meta/access 의 추가 계정)만 통과, 아니면 안내 화면
- 탭 4개(대시보드·업체 관리·사업 관리·설정) 빈 화면, 다크/라이트 전환, 글자 크기 가−/가+(가운데에 현재 크기, 누르면 기본)
- ?demo=1 이면 Firebase 대신 가상 데이터(demo/data.js: 가상 업체 40곳·사업 4개·이슈 몇 건, 실제 업체 이름 금지)로 동작하게
- Firestore 규칙: 로그인 + 이메일 인증 + (관리자 또는 meta/access 에 있는 이메일)만 읽기·쓰기
- GitHub Pages로 여는 방법과 Firebase 승인된 도메인 추가 방법을 알려줘
```
확인: `?demo=1`로 탭 4개가 열리고, 실제 주소에서는 허용 계정으로만 로그인된다.

### 3-2. 업체 관리 · 사업 관리 (약 1시간)

```text

  체크박스 선택 삭제, 업체명을 누르면 오른쪽 창에 상세. 일괄 등록: 엑셀/CSV 올리기 또는 표 붙여넣기 → 미리보기 → 등록
- 사업 관리: 사업 카드(사업명·국가·담당자 '내 사업'), 역할 칸 F/S → 컨설턴트 → 본구매, 왼쪽 업체 목록에서 끌어다 놓기,

```

## 4. 시행착오에서 나온 결정 (B안에서 꼭 지킬 것)

| 결정 | 이유 |
|---|---|
| 대시보드는 GitHub를 직접 부르지 않고 Firestore에 '실행 요청'만 | 회사망에서 api.github.com 차단 |
| Apps Script 타이머가 GitHub 실행을 깨움 | GitHub 자체 예약(cron)은 늦거나 빠지는 일이 잦음 |
| workflow 파일은 사람이 마지막으로 커밋 | 봇이 마지막으로 고치면 예약 실행이 멈출 수 있음 |
| '위험'은 지금 제재 중일 때만 | 뉴스는 확정이 아니라 신호 — 위험이 너무 많으면 아무도 안 봄 |
| 스캔은 변경분만(seen), 화면 새로고침은 상태 1건만 | Firestore 무료 한도 초과로 하루 멈춘 적 있음 |
| 같은 이슈 묶기 | 같은 사건을 여러 매체가 보도하면 목록이 도배됨 |
| EXIMIIS 업로드 검사(상태·제재기간 열 필수) | 업체 명단을 잘못 올려 가짜 제재 기록 191건이 생긴 적 있음 |
| 공개 로그는 건수만, HTTP 요청 로그 끄기 | 검색 주소에 업체 이름·사업자번호가 들어감 |
| 시각은 한국시간 기준 계산 | 실행 서버(UTC)와 9시간 차이로 '주 1회'가 8일마다 돌았음 |
| 위험·경고·주의 버튼 = 업체 목록 | 아래 이슈를 거르면 '3곳인데 0건'처럼 숫자가 어긋나 보임 |
